# verb: trace（追根 + 压）

**一句话**：追根溯源，持续施压，系统自现。**不是够用，是想通。**

## 输入
- `problem.one_line`
- 已有的解释（用户给的因果说法）

## 动作

### 1. 追（不追到根不罢休）
连问"再往下是什么"，每次把答案当成新的现象：

```
现象：视频号做不起来
↓ 为什么？ 内容没人看完
↓ 为什么？ 前 3 秒没钩子
↓ 为什么？ 我不写钩子，因为我不知道给谁看
↓ 为什么？ 我从来没定过"这条是给谁的"
↓ 为什么？ 我把它当作品，不当产品   ← 这是根：定位问题，不是执行问题
```

**停止条件**：再问一层，答案会变成"因为我懒/我不够努力"——那说明上一层的已经不是根，是情绪。**根通常是"一个没做过的决定"，不是"一个没做到的品质"。**

### 2. 找关键（瞄准器）
一句话说出关键变量。说不出 → 回到第 1 步重追。

### 3. 压（缩小"没有"的范围）
压不是用力，是**缩小范围**。

- 列出"我还不知道的东西"清单（这就是 `open_frontier`）
- 每次压，只做一件事：把范围缩小一格，看里面露出什么结构
- 面团比喻：不压不知道里面什么形状；压一下紧一分，结构出来一点

> 压不是填坑，是**让结构自己露出来**；压不是一次，是**持续，直到显形**。

### 4. 验系统（验"系统在转"，不验"结论对不对"）
写出 ≥1 条**领先信号**：什么现象出现，说明结构开始转了（通常出现在结果之前）。

## 输出字段
```yaml
root_chain: [{question, candidate, status: kept|rejected, why}]   # ≥2 条，≥1 条 rejected
open_frontier
signals.system_turning
```

## 判据
- 至少一个候选根**被否掉**（没否掉任何东西 = 只追了一层）
- `open_frontier` 非空（全想通了的人通常是没想）
- 根写的是"一个决定"，不是"一种品质"

## 反模式
| 假根 | 为什么是假的 |
|---|---|
| 执行力不够 | 这是现象的名字，不是原因 |
| 认知不够 | 无法证伪，无法行动 |
| 不够努力 | 同上，且导向"多干"而不是"换个干法" |
| 行业不行 | 如果成立，同行业的人应该一样差——用一个反例就能推翻 |

## 与本仓库其他部分的关系
`trace` 是 `diagnose` 和 `retro` 的地基；`lenses/failure-list.md` 用它定位最早失效点。

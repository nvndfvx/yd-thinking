# verb: frame

**一句话**：把模糊的问题压成一个可判的问题。这一步做砸，后面全白干。

## 输入
- 用户的原始说法

## 动作（按顺序）

1. **删万能词。** "如何""怎么""怎样"→ 换成具体对象。剩下的如果还是一句空话，说明问题还没成形。
2. **把"要不要"变成"在 ___ 和 ___ 之间选"。** 只有列不出对手项，就不是选择，是许愿。
3. **补三个事实**：谁来定（`owner`）、什么时候必须定（`by_when`）、现在的资源边界。
4. **检一遍是不是在找认同。** 如果用户已经说了答案、只是在问"对吧"，先说破。
5. **判四轴**：`settled / choose / multi / oneway`（见 `router/axes.yaml`）。

## 输出字段
```yaml
problem: {one_line, owner, by_when}
run.axes: {settled, choose, multi, oneway}
run.reversibility
```

## 判据
- `one_line` 里有**具体对象**和**具体时限**
- 能一眼看出这是"选"还是"搞不懂"还是"做不起来"

## 反模式
| 病 | 例 |
|---|---|
| 一句话塞两个问题 | "我要不要辞职去创业"→ 先拆成"辞不辞"和"创不创" |
| 问题里含答案 | "我怎么才能说服他"→ 真问题是"他不认同我怎么办" |
| 无时限 | "长期来看我要不要转行"→ 没有 by_when 就判不了 |
| 轴不清硬判 | 缺 settled / choose → 走 INSUFFICIENT，**不要猜** |

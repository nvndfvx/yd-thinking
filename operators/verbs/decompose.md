# verb: decompose

**一句话**：把一团问题拆成并存的维度，或拆成有关系的部件。**拆错就全错。**

## 输入
- `problem.one_line`

## 动作

1. **先分清两种拆法**（这是最容易混的地方）：
   - **维度**：并存的、可以同时要的（收入 / 时间 / 成长 / 关系）
   - **选项**：互斥的、只能选一个的（去 A 公司 / 去 B 公司 / 不去）
   > 把选项当维度，会得出"两边都要"的假结论；把维度当选项，会逼出没必要的取舍。
2. **至少 3 个。** 2 个维度通常只是"好处"和"坏处"，等于没拆。
3. **每个维度问两件事**：
   - 它是阴还是阳？（是积累/骨架/慢的，还是输出/表层/快的？）
   - 它是支点还是杠杆？（不动的，还是围绕支点积累的？）
4. **找拉扯。** 哪两个维度在互相抢同一份资源（时间/钱/注意力）？这就是 `key conflict` 的候选。
5. **找接口。** 哪两个维度可以互相转化（A 的弱变 B 的强）？这是 `pivot` 的候选。

## 输出字段
```yaml
weights[].dimension
opposing_forces.yang / yin
```

## 判据
- 维度之间**互不包含**（"收入"和"涨薪"是同一个维度）
- 至少有一对维度在抢同一份资源

## 反模式
- 维度全是同义词（成长 / 进步 / 提升）
- 只拆"好处"和"坏处"两栏
- 拆完发现所有维度都指向同一个答案 → 没拆，只是复述

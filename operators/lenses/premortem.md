# lens: premortem（尸检）

> **假设这件事已经在 6 个月后彻底失败了，现在写它的尸检报告。**
> 不是"可能有什么风险"，是"它已经死了，死因是什么"。

## 为什么需要它

- 风控（`choose` 第 3 步）能列出**想得到的**风险
- 尸检能逼出**想不到的**风险——因为"已经失败"这个前提取消了自我辩护

`oneway=true` 且**尚未发生**时强制；复盘（settled）场景可选——那时它给的是"下次再犯"的预演。

## 五个问题（按顺序，不许跳过）

1. **它死在哪一步？**（`failed_at`）—— 具体到月份和事件，不是"后来就不行了"
2. **最致命的原因是什么？**（`causes[0]`）—— 写下你**最不愿意承认**的那个
3. **第二、第三个死因？**（`causes[1..]`）—— ≥2 条，从最致命写起
4. **最早能看出苗头的信号是什么？**（`earliest_signal`）—— 它在失败前多久出现
5. **当时如果看到那个信号，我会做什么？** → 这就是现在该做的准备

## 输出字段

```yaml
premortem:
  failed_at: str
  causes: [str]          # ≥2 条
  earliest_signal: str
```

## 判据

- `causes[0]` 读起来让人不舒服 → 合格
- `causes[0]` 是"市场环境不好"→ 不合格（不可控因素不是尸检结论）
- `earliest_signal` 能被第三方观测 → 合格

## 反模式

| 病 | 说明 |
|---|---|
| 写成风险清单 | 风险清单是"可能"，尸检是"已经" |
| 死因全是外部因素 | 那份报告对自己的行为零信息量 |
| `failed_at` 写成"某个阶段" | 不具体就无法倒推信号 |
| 只写 1 条死因 | 失败从来不是单因 |

## 一句话

**能在事前把失败讲具体的人，才配得上"我觉得这个能成"。**

# Router Fallback：轴判不出来的时候

## 1. 先尝试从问题里读轴

不要一上来就问用户。先按下面的线索读，读得出来就直接走：

| 轴 | 问题里的线索 | 例 |
|---|---|---|
| `settled=true` | 过去时、"为什么失败了"、"当时"、"复盘" | "上次创业为什么失败" |
| `choose=true` | "要不要"、"该不该"、"选哪个"、"值不值得" | "我要不要买大疆" |
| `multi=true` | 出现 ≥2 个利益方，或"既…又…"、"但是"句多 | "想涨薪又不想加班，还要顾家" |
| `oneway=true` | "辞职"、"分手"、"投全部钱"、"签合同"、"公开" | "要不要退学" |
| `structure=true` | "剧本"、"故事"、"第二幕"、"人设"、"内容" | "这个剧本第二幕塌了" |
| `choose=false` | "做不起来"、"找不到发力点"、"怎么突破" | "我的视频号做不起来" |

## 2. 判不出来的，只问 ≤2 个问题，然后停

按影响大小排序，优先问这两个（它们改变 primary 的结果）：

1. **"这件事已经发生了，还是还没发生？"**（决定 retro / 非 retro）
2. **"你是在几个选项里选一个，还是不知道从哪使劲？"**（决定 choose）

`oneway` 判不出来时**不要问**，直接假定 `oneway=true`（保守）。

问完就停。**不许一边问一边先给结论。**

## 3. 缺轴的降级表

| 缺失 | 降级处理 | 理由 |
|---|---|---|
| `settled` | 必问，不能猜 | retro 与其他流程的根因逻辑完全不同 |
| `choose` | 必问，不能猜 | 决定是完全不同的两条路 |
| `multi` | 默认 `false` | 多算的代价（多称一次重）小于漏算 |
| `oneway` | 默认 `true` | 漏判不可逆的代价远大于多做一次风控 |
| `structure` | 默认 `false` | 除非明说是内容创作 |

## 4. 禁止

- ❌ 让模型自由发明流程或算子——只能从 `operators/` 现有文件里选
- ❌ 用"这题比较综合"当理由直接跑全部流程（现在的 `R8_full_analysis` 就有这个毛病：它是"我不知道"的伪装）
- ❌ 在轴不清时给出 confidence=high

# 示例 6：有公司在挖我，要不要去

> 覆盖：`INSUFFICIENT`（信息不足，拒答）——**本技能最值钱的一个状态。**
> 演示重点：**缺的格会改变结论时，问 ≤2 个问题，然后停。不硬编。**

## 四轴（能读出来的部分）

```yaml
settled: false
choose: true        # 去 / 不去，互斥
multi: ?            # 不知道有没有家庭、房贷等约束
oneway: ?           # 不知道去了还能不能回来
```

`multi`、`oneway` 判不出来时：`multi` 默认 false、`oneway` 默认 true（保守）。
但**真正缺的不是轴，是决定方案的关键事实**——金额、期限、退路。这三样任意缺一，结论都会变。

所以：**走 INSUFFICIENT，问 2 个问题，停。**

## 输出（固定三行，不多说一个字）

```
我需要先知道两件事：
1. 对方给的薪资和条件，以及你现在这份的薪资（具体数字，不是"还不错"）。
2. 这个 offer 有多长有效期，你拒了之后还回得来吗？

（拿到这两个答案我再判。现在给结论会是编的。）
```

---

## 为什么这个示例单独成篇

1. 它教会模型**说"我不知道"的权利**——这是 v0.1 完全没有的状态，老版本会硬给一个"建议你去"。
2. 它给"拒答"一个固定格式，而不是让模型自由发挥（自由发挥会变成"多提供一些背景"这种空转）。
3. 它是评测里的硬用例：任何把 INSUFFICIENT 处理成普通决策的模型，在这个 case 直接判失败。

## 判据（什么情况下不该拒答）

- 用户已经给了金额和期限 → 不该再问，直接判。
- 缺的东西不影响结论（比如"他什么风格"）→ 不该问，先给。
- 用户催"你就说去不去" → 仍然拒答，但换成一句："去不去的分界是工资比现在高 40% 以上，你告诉我这个数，我立刻给。"

**拒答不是礼貌，是纪律。**
